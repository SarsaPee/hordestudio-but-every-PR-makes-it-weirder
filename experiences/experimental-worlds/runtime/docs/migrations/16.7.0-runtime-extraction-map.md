# 15.9.2 Runtime-Only Extraction Map

## Scope

This document maps behavior present in the full sibling `hordestudio` runtime
but absent from `legacy/15.9.2-custom`. It is an extraction guide, not a patch:
line numbers refer to the current full runtime and will move as that runtime is
edited.

The raw fork-to-runtime delta is too large to migrate as one change:

| File | Added | Removed |
| --- | ---: | ---: |
| `app.js` | 12,188 | 1,258 |
| `index.html` | 632 | 82 |
| `style.css` | 1,071 | 71 |
| `horde_mcp_bridge.py` | 494 | 4 |

## Extraction boundaries

### 1. Canonical presence and Melbourne state adapters

- Primary `app.js` anchor: `MELBOURNE_STATE_KEYS` near line 9,884.
- Includes explicit scene-presence normalization and Melbourne receipt fields.
- Split target:
  1. generic explicit-presence/session helpers;
  2. generic receipt field extension mechanism;
  3. Melbourne-only field registration.
- Generic code must not embed Melbourne entity IDs or field names directly.

### 2. Semantic location memory and unresolved spatial references

- Primary anchors begin near `WORLD_LOCATION_EMBED_CHUNK` at line 10,185.
- Includes stable location embedding text, ancestry, semantic candidates,
  unresolved-place records, classification, embedding and later assignment.
- Depends on canonical location IDs and episodic/world-history prerequisites.
- Must remain semantic discovery only; containment, pathfinding and movement
  legality stay in authoritative spatial/traversal reducers.

### 3. Character cognition and NPC observations

- Primary anchors begin near `NPC_OBSERVATION_EPISTEMIC_STATUSES` at line
  10,512 and `ensureCharacterCognitionLedger` at line 10,531.
- Includes first-person experiential records, epistemic status, provenance,
  character-scoped retrieval, accessibility and provisional cognition.
- Extract as a generic cognition module with an optional Melbourne adapter.
- Do not port the old transcript-copy observation behavior.

### 4. Vectorization status and manual actions

- Primary UI/runtime anchor: `renderVectorizationPanel` near line 11,371.
- Includes pool scanning, stale/missing status, manual vectorization and cache
  control.
- Later inspector settings and actions continue near line 40,691.
- Separate model/configuration, job execution and inspector presentation so the
  vector worker is not coupled to World Studio DOM state.

### 5. World persona

- Primary anchor: `personaPrefillSourceFromActiveSession` near line 14,771.
- Includes active persona selection, chat-derived generation, streamed
  reasoning/draft display and continuation after truncation.
- Port after reviewing the 16.7.0 persona/session model.
- Persona identity must remain name/ID based, not role-label based.

### 6. World Architect spatial structures

- Primary range begins at `addWorldLocation` near line 16,371.
- Spatial constants and schemas begin near `WORLD_TRAVERSAL_TYPES` at line
  18,157.
- Includes building modes, floors, explicit parentage, hierarchy validation,
  semantic map editing and structure passes.
- `runWorldArchitectStructurePass` begins near line 21,104.
- Split into schema/normalization, mutation API, map/editor UI and AI structure
  pass commits.

### 7. Traversal methods and vehicle ownership

- Primary normalization anchor: `normalizeWorldTraversalData` near line 18,506.
- World Studio presentation begins at `renderWorldTraversal` near line 21,339.
- Includes point-to-point versus route coverage, authority, exclusions, stops,
  vehicle entities, ownership/access and journey behavior.
- Port schema and resolver behavior before the editor UI.
- Vehicle identity remains an Entity concern; moving interiors are runtime
  Journey containers rather than authored World Architect locations.

### 8. Sidecar backstage and communication UI

- Message handoff presentation begins at `renderWorldHandoffThread` near line
  27,298.
- Includes Narrator-to-Sidecar handoff, reconciliation receipt, next-beat packet
  and direct Sidecar conversation rendering.
- Extract after the protocol records are established so UI does not become the
  persistence contract.

### 9. Sidecar protocol and direct conversation

- Main protocol anchors:
  - `isSemanticSidecarWorld` near line 28,307;
  - `ensureSidecarProtocol` near line 28,311;
  - `buildSidecarScenePacket` near line 28,402;
  - `executeSidecarConversation` near line 28,549.
- Includes questions, answers, requests, accepted player details, semantic
  handoffs, direct refinement and next-turn packets.
- Must remain a two-call normal-turn pipeline. Unresolved questions are queued
  into a later Narrator turn; they do not trigger a third Narrator call.
- Sidecar conversation is out-of-world and must not append a roleplay message or
  advance canonical time.

### 10. Semantic time

- Primary clock-mode anchor: `getWorldClockMode` near line 32,970.
- Includes starting-life time, 12-hour display and Sidecar semantic time.
- Extract narrative temporal evidence separately from exact mechanical clock
  normalization.
- Do not port natural-language-to-duration lookup tables as authorial rules.
- Inline automatic tick behavior remains Legacy-only where compatibility needs
  it.

### 11. Journey and runtime vehicle containers

- Session traversal state begins at `normalizeSessionTraversalState` near line
  33,191.
- Runtime vehicle creation begins at `createRuntimeVehicleContainer` near line
  33,384.
- Includes boarding, occupancy, journey creation, arrival, exit and prompt
  context.
- Mechanical duration constrains authored travel but must not independently
  author boarding, movement or arrival.
- Requires the canonical traversal schema from extraction boundary 7.

### 12. Inline receipt repair extensions

- Primary anchor: `RECEIPT_REPAIR_REASONING_TOKEN_DEFAULTS` near line 37,353.
- Includes the local model/provider/retry controls and additional repair calls.
- Disposition: Legacy only.
- Do not migrate into Sidecar. Port only if explicit Inline Legacy compatibility
  requires behavior beyond stock 16.7.0 receipt repair.

### 13. Episodic consolidation and derived memory

- V2 derived memory entry point: `deriveWorldChunkMemoriesFromEpisodeV2` near
  line 40,087.
- Episodic archiving entry point: `consolidateSessionEpisodicMemory` near line
  40,350.
- Includes prerequisite gating, per-character cognition calls, spatial
  references, provenance, prior-vector consultation, catch-up and gap repair.
- Extract episodic archiving first, then derived NPC/location processing as a
  downstream stage.

### 14. Vector Memory Inspector settings and deletion

- Inspector scoping begins at `configureVectorInspectorScope` near line 40,691.
- World/global setting inheritance begins at `WORLD_MEMORY_PANEL_FIELDS` near
  line 40,705.
- Includes character and location filters, generation/catch-up actions,
  contextual deletion, progress/concurrency and consolidation audit UI.
- Destructive actions must be scoped to the selected pool. Delete-all must never
  delete unrelated chat/session state.

### 15. Background World Agent proposal path

- Current reasoning controls originated in sanitized commit `5be77a7`.
- Additional runtime work must be located around World Agent prompt/result
  assembly during the generation-path audit.
- Target behavior is proposal-only: the World Agent supplies candidate changes
  to Sidecar, which accepts, rejects or refines them before reducers run.

### 16. Melbourne modules and content

- Runtime-only top-level modules include:
  - `melbourne-mechanics.js`;
  - `melbourne-bunnyrx-registry.js`;
  - `melbourne-ff5-preset.js`;
  - `melbourne-ff52-preset.js`;
  - `melbourne-world.js`.
- Supporting build and repair scripts live under `scripts/`.
- Migrate after generic registration points exist.
- Keep private/live exports, logs, process IDs and `.env` files outside Git.

## Extraction rule

No boundary above is migrated by copying the complete current `app.js`,
`index.html`, `style.css` or bridge. Each unit is re-applied to stock 16.7.0 as
one or more commits whose message identifies both this map entry and its legacy
source.
