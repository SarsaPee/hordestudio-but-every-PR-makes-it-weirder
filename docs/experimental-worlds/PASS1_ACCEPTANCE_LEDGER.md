## Baseline defect discipline

The Melbourne temporal/date inconsistency remains a pre-existing baseline
issue. It is not being changed during this extraction unless a test proves the
split introduced a regression.

The existing settings cache-bundle audit expects all three original host assets
to share one version token, but the preserved custom 17.0 document already
served separate tokens before this split. It is recorded as a baseline audit
expectation mismatch, not an Experimental runtime defect; no Settings behavior
was changed to satisfy it.
