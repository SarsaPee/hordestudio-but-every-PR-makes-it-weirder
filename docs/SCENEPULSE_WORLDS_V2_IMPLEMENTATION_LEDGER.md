# ScenePulse Worlds V2 implementation ledger

This ledger is governed by [Build ScenePulse in Worlds V2](SCENEPULSE_WORLDS_V2_BUILD_THE_PRODUCT.md). Statuses are **not started**, **ported**, **wired**, **demonstrated**, and **blocked**. “Demonstrated” below means demonstrated against the sealed source tutorial fixture unless it explicitly says “real Horde turn.” No Gate-A row is a claim of a model call, persistence, or production data.

Pinned source: `xenofei/SillyTavern-ScenePulse` at `2888d0d748033c5b16eac410f5396af055142483` (v6.27.20). Original source lives at `scenepulse/vendor/ScenePulse/`. The live render path is `scenepulse/horde/scenepulse-source-runtime.js`; `scenepulse/horde/scene-pulse-worlds.js` is retained only as a historical migration reference and is not invoked by Worlds. Gate A receives only `{status: 'accepted_fixture', scenePulse: TOUR_EXAMPLE_DATA}`. Gate B accepts a settled, exact-turn Reader handoff plus that sealed fixture as its field-by-field fallback. If the newest authored turn is not settled, the foreground retains the last such accepted handoff as visibly `Last known scene`; the newer handoff and questions remain in Backstage.

## Mechanical phase boundary

1. The original ordered ScenePulse stylesheet is served whole, then only the small native-runtime geometry and provenance layer needed to let the upstream DOM take over the World surface.
2. `renderScenePulseWorldsWorkspace()` mounts `HordeScenePulseSourceRuntime` and returns before `buildSidecarWorkspaceModel()` or any legacy adapter can execute. Its only Gate-B selection path is `scenePulseAcceptedHandoff()`, which reads a settled snapshot for the exact current authored turn, or visibly retains the last exact settled snapshot while the newer turn remains unresolved in Backstage.
3. The native runtime accepts only `accepted_fixture`, `accepted_live`, or the explicit direct-human edit overlay. An `accepted_live` handoff composes `fixtureScenePulse` with only the selected settled Reader's `scenePulse` projection; `lastKnown` never treats an incomplete newer Reader response as source data.
4. The normal source tracker materialization contains no route to `world.entities`, `model.snapshots`, Horde's draft, or a live registry. The development-only `Inspect` comparison may resolve a Reader-supplied *specific canonical ID* beside a candidate handoff; it never supplies, completes, or rewrites a visible ScenePulse tracker field.
5. Gate B now provides per-field provenance: a source field stays fixture-backed and carries a visible `Fixture` chip until the settled Reader replaces that one field. It will never disappear merely because live wiring is incomplete. Where a vendored source surface has a compound dependency, its fixture support stays together: an incomplete relationship collection keeps its populated fixture relationship cards and their matching fixture dossiers rather than letting the source filter manufacture an `unknown` relationship stub.
6. Gate B uses compact changed-only Reader deltas. A ScenePulse record patch preserves every unmentioned field in its prior accepted projection; it accepts both source arrays and compact stable-ID maps, normalizing the latter only at the reducer boundary. Current `charactersPresent` is the explicit per-turn membership assertion; whole collection replacement is opt-in and named. Each accepted snapshot retains its own exact raw packet for Inspect while its separate envelope remains the deterministic merged projection. A focused refresh cannot replace omitted sections with the tutorial fallback or apply signed meter movement twice at render time.
7. The on-demand `Inspect` surface shows the actual ScenePulse value, accepted Sidecar value, current scaffold route, and compact delta. It is deliberately read-only: a mismatch remains visible until a field mapping/authority decision is made through the owning integration path, rather than being silently overwritten.
8. Any proof recorded against the retired adapter is migration evidence only. Native-runtime parity needs its own browser pass before a row is treated as re-demonstrated.
9. The vendored NPC Relationship Web remains the foreground graph renderer. Its Generate/Refresh action crosses one named `requestScenePulseRelationshipGraph` seam to the exact-turn Sidecar Reader; it never invokes the source quiet-prompt provider path in Worlds. A Reader graph is accepted only when its declared roster exactly matches the visible source character roster. Otherwise it remains visibly withheld in `Inspect`, rather than being completed from Horde’s registry or a stale graph cache.
