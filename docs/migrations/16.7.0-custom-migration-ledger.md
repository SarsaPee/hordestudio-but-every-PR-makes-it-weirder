# Horde Studio 16.7.0 Custom Migration Ledger

## Purpose

This ledger controls the migration from the customized Horde Studio 15.9.2
runtime to the sanitized `16.7.0` branch. The branch is rooted directly at the
official `v16.7.0` tag (`1cb528a31d620edb1a5e3e2ebf582474c0773f64`).

The migration is stock-first:

1. Keep the upstream 16.7.0 implementation intact.
2. Port one named feature at a time.
3. Preserve validators and reducers as the canonical commit boundary.
4. Keep Inline receipt extraction and repair available only as Legacy behavior.
5. Do not allow Legacy classifiers or repair calls to run in the Sidecar path.
6. Keep Melbourne content separate from generally reusable Horde features.

## Migration dispositions

- **Carry**: preserve the feature, adapting its integration points to 16.7.0.
- **Review**: preserve the intent only after checking newer upstream behavior.
- **Legacy**: retain on `legacy/15.9.2-custom`; only port the minimum required
  for explicit Inline Legacy compatibility.
- **Fold**: absorb a small corrective commit into the feature it repairs.
- **World-specific**: migrate after the generic runtime is stable; do not mix it
  into a generally upstreamable commit.
- **Split**: separate a mixed commit into independently reviewable behavior.

## Inline Legacy boundary

The upstream 16.7.0 code still contains receipt-repair behavior. It may remain
available when a world explicitly uses Inline Legacy mode. Sidecar mode must
not call the Chronicle Classifier, receipt repair, or an automatic third model
call.

Sidecar failure behavior is:

1. Validate and commit established fields from a usable reconciliation.
2. Leave unsupported or unresolved canonical state unchanged.
3. Persist questions for a later normal Narrator/Sidecar cycle.
4. Record malformed or failed calls in audit data.
5. Never fall back silently to Legacy extraction or repair.

## Port order

1. Inventory 16.7.0 persistence, world schema, prompt assembly, generation paths,
   reducers, traversal and World Studio integration points.
2. Port generic provider routing and shared-library infrastructure.
3. Port safe independent UI and rules features.
4. Port dossier claims and canonical entity/state primitives.
5. Extract and port Sidecar records, persistence and shared reducer boundary.
6. Port the two-call Narrator/Sidecar generation loop and backstage UI.
7. Port semantic time, traversal and vehicle reconciliation.
8. Port memory/vectorization and persona features.
9. Adapt the Background World Agent into Sidecar-reviewed proposals.
10. Migrate Melbourne mechanics, build scripts and content last.

## Commit policy for `16.7.0`

- One coherent feature or prerequisite per commit.
- No private world exports, local logs, credentials, browser data or generated
  caches.
- Generic engine changes must not depend on Melbourne IDs or names.
- World-specific modules must use explicit registration/integration points.
- Every persistence change documents its schema version and migration behavior.
- Every port records its originating legacy commit or runtime source range in
  the commit message.
